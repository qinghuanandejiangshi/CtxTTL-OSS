# 架构

[English](../../ARCHITECTURE.md) · [中文文档中心](README.md)

CtxTTL 按可替换层组织。依赖方向指向稳定的领域契约；领域代码不导入 HTTP、数据库、Agent
框架或模型供应商的具体实现。

```text
API / CLI
    ↓
应用服务
    ↓
领域模型与端口
    ↑
基础设施适配器
```

## 模块边界

| 区域 | 负责 | 不应负责 |
|---|---|---|
| `models` | 供应商无关的 Context IR 与生命周期事件 | HTTP、SQL、供应商载荷 |
| `identity` | 解析明确的所有权与隔离边界 | 身份认证、持久化 |
| `config` | 解析和校验运行配置 | 业务决策 |
| `api` | HTTP 协议转换与依赖组装 | 上下文选择策略 |
| `application` | 通过接口协调用例 | 特定框架的传输细节 |
| `archive` | 原始对话归档模型与检索端口 | 编译策略、SQL |
| `compiler` | 纯上下文编译策略 | 数据库与网络 I/O |
| `storage` | 持久化端口与可替换适配器 | 编译策略 |
| `providers` | 上游 LLM 传输适配器 | 持久状态与检索策略 |
| `observability` | 结构化 Trace 与指标 | 业务决策 |
| `benchmarks` | 确定性回归 Fixture 与策略契约 | 生产请求处理 |
| `evaluation` | 模型/Judge 端口、检查点、证据链和配对指标 | 生产请求处理、编译策略 |
| `integrations` | 通用身份契约之上的旧版兼容适配器 | Agent 循环、模型选择、生命周期策略 |
| `packages/ctxttl-mcp` | 基于 Core 公开 HTTP 契约的可选 MCP 控制面适配器 | 编译器、存储、模型调用、Agent 循环 |

只有当一个未来模块拥有首个真实能力时才创建它，不预先保留空目录。

## 依赖规则

1. 领域模型只能依赖 Pydantic 和 Python 标准库。
2. 编译策略通过参数接收数据并返回显式结果，不使用全局设置、网络客户端或数据库连接。
3. 存储和模型供应商实现只实现消费方拥有的窄接口。
4. FastAPI 对象只存在于 API 层。
5. 除非有明确编译规则，供应商特有字段在协议边界必须无损保留。
6. 公共行为通过契约测试；每种适配器实现可以复用同一组契约测试。
7. 跨模块导入必须遵循上述依赖方向，循环依赖属于缺陷。
8. Agent 运行时直接使用通用 HTTP 或应用身份契约；旧版集成可以转换外部坐标，但不复制编译或
   持久化逻辑，也不需要为每个新框架各写一份。
9. Benchmark 工具可以依赖生产包，但生产模块绝不能导入 Benchmark 代码。
10. 可选集成包只能依赖公开 HTTP 或应用契约；Core 绝不导入其 SDK 或实现模块。
11. 供应商协议适配器可以把显式请求项转换到编译器的稳定消息边界，但必须以原子方式保留
    不透明项，也不得持有生命周期策略。

## 变更纪律

- 一个提交表达一个连贯能力或重构。
- 条件允许时，重构与行为变更分开提交。
- 每项行为变更都在最低有效层增加测试。
- 破坏性契约变更必须在 `docs/decisions/` 下增加架构决策记录。
- 密钥、本地数据库、含私有内容的 Trace 和 `.env` 文件永不提交。
