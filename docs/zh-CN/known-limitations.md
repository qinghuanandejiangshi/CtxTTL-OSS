# 已知限制

[English](../known-limitations.md) · [中文文档中心](README.md)

CtxTTL 0.2.1 是研究 MVP，以下边界是当前有意保留并必须公开说明的：

- 当前代理 Chat Completions、Responses `POST /responses` 的“显式无状态”子集，以及通过
  `GET /models` 执行的只读模型目录发现。compile
  模式下，使用 `previous_response_id`、托管 Conversation 或托管 Prompt 的请求会失败关闭，
  因为代理无法对隐藏上游状态执行生命周期过滤；其他 Responses 资源端点和 WebSocket 未实现。
- 通用协议不负责任何 Agent 循环。OpenClaw 专用接口只是旧版兼容转换。可选 MCP 包仍是生命周期
  控制面；只有经过模型代理的数据请求才会在每次调用时强制编译。
- 身份 Header 定义隔离坐标，但不提供认证。没有身份认证和授权层时，不应服务不受信任租户。
- 多 Agent 作用域隔离与共享已通过本地契约测试，但要声称广泛兼容，仍需在多个独立 Agent
  运行时上完成黑盒验证。
- 输出捕获支持常见 Chat Completions 普通/SSE 格式与 Responses 终止事件；过大、畸形、失败
  或取消的流不会被视为完整输出。
- SQLite FTS5 检索是词法检索。v0.2 核心没有向量搜索、学习型重排器或语义抽取模型。
- 权限标签和“仅证据”包装可以降低检索文本意外提升为指令的风险，但 Prompt 边界无法保证完全
  抵御恶意检索内容中的提示词注入。
- 结构化事实、决策、约束和任务状态需要调用方显式写入；CtxTTL 不宣称能够可靠地自动抽取。
- Token 估算器确定、无额外依赖，但只是近似值；可在端口后替换为供应商原生 tokenizer。
- 重放只有在保存输入快照时才精确；生产环境必须在可复现性与敏感数据最小化之间自行选择。
- 默认 SQLite 适配器面向本地单进程研究，不适合高并发或分布式生产部署。
- Benchmark 和模型评测证明的是特定冻结协议，不等同于线上质量、普适优势或商业效果。
- 当前没有管理界面、多租户控制面、计费、托管部署或自动数据迁移服务。

详细安全部署边界见 [安全策略](../../SECURITY.md)，后续范围见[路线图](../roadmap.md)。
