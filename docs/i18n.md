# Documentation localization

Documentation localization is a repository concern, not a CtxTTL runtime service. Model prompts,
context lifecycle semantics, API field names, and stored values remain language-neutral. Human
documentation is organized as replaceable locale packs around stable page identifiers.

`docs/locales.toml` is the source of truth. Each entry maps one conceptual page to one file per
supported locale. Repository hygiene checks fail when a locale is missing a required page, a path
does not exist, a page identifier is duplicated, or an undeclared locale appears in a mapping.

To add a language:

1. Add its BCP 47 locale code to `locales` in `docs/locales.toml`.
2. Create a locale directory such as `docs/ja/`.
3. Add that locale's path to every page mapping.
4. Add reciprocal language navigation at the top of translated pages.
5. Run `python scripts/check_repository_hygiene.py` and the test suite.

Only human-facing prose is translated. Code symbols, HTTP headers, JSON fields, command lines,
benchmark identifiers, hashes, and statistical values stay unchanged so translations cannot
silently change the technical contract. A website can later render the same manifest into a
language selector; no network service is required until documentation becomes a separately
deployed product.
