# CtxTTL MCP

CtxTTL MCP is a standalone control-plane adapter for CtxTTL Core. It lets Codex and other MCP hosts
assert, supersede, retract, expire, inspect, and compile lifecycle-aware context without importing
MCP dependencies into the Core runtime.

The package talks only to the documented CtxTTL HTTP API. It does not import Core internals and it
does not intercept model calls. Core's separate Responses API gateway is the authoritative data
plane for transparent request compilation.

## Install

From the repository root:

```powershell
.\.venv\Scripts\python.exe -m pip install -e packages\ctxttl-mcp
```

Start CtxTTL Core on port `8765`, then configure and run the MCP process:

```powershell
$env:CTXTTL_MCP_CORE_URL = "http://127.0.0.1:8765"
$env:CTXTTL_MCP_BEARER_TOKEN = "replace-with-a-long-random-token"
.\.venv\Scripts\ctxttl-mcp.exe
```

Register it with Codex without putting the token in configuration:

```powershell
$env:CTXTTL_MCP_TOKEN = "replace-with-the-same-token"
codex mcp add ctxttl --url http://127.0.0.1:8766/mcp --bearer-token-env-var CTXTTL_MCP_TOKEN
codex mcp list
```

## Tools

- `ctxttl_context_assert`
- `ctxttl_context_supersede`
- `ctxttl_context_retract`
- `ctxttl_context_expire`
- `ctxttl_context_list`
- `ctxttl_compile_request`
- `ctxttl_trace_get`

Every operation requires an explicit `session_id`. Agent, project, user, task, and turn coordinates
are optional, but a scope that requires one of them is rejected by Core when the corresponding
coordinate is missing. The same coordinates are used by Core's HTTP data plane, so the MCP package
does not maintain framework-specific identity mappings. Mutation request IDs are generated by the adapter and passed to Core for correlation and
for idempotency where the Core endpoint supports it.

`ctxttl_compile_request` does not call a model, but it is intentionally not a read-only preview:
Core records a trace/archive entry and observes turn-scoped lifecycle state during compilation.

## Diagnostics and security

Logs are emitted as JSON. They include tool name, generated request ID, elapsed time, error type,
and a one-way session fingerprint. Context values, raw session identifiers, authorization headers,
and bearer tokens are never logged by the adapter.

Set `CTXTTL_MCP_LOG_LEVEL=DEBUG` for transport diagnosis. Core rejections retain their safe error
code; network failures become `CoreUnavailable`, malformed responses become `CoreProtocolError`,
and lifecycle or identity rejections become `CoreRejected`.

The default listener is loopback-only. A non-loopback bind is rejected unless a bearer token is
configured. Static bearer protection is intentionally small and is not a replacement for TLS,
OAuth, rate limits, tenant authorization, or an enterprise API gateway.
